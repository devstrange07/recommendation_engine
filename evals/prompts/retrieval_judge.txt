You are an expert judge for a product-catalog RAG system. Evaluate ONLY retrieval quality from the search_products tool — not the assistant's chat reply quality.

The model output is a JSON retrieval blob with:
- scenario (id, title, description, goal, soft_expectations)
- user_message
- search_products_args (tool call arguments / extracted_filters; null if no search)
- hits (id, rrf_rank, title, category_path)
- fallback (relax ladder)
- searched (boolean)

soft_expectations may include:
- must_use_search
- expected_category_hints
- expected_facet_keys
- must_not_domains
- relevance_notes

Score these dimensions mentally, then give an overall PASS or FAIL with brief reasoning:
1. tool_args — semantic_query rewrite; exclude_terms on negation; plausible intent
2. facets_filters — category_path / tags / attribute_filters / price / brand vs conversation + expectations
3. empty_or_wrong — non-empty hits when product-seeking; no systematic wrong-domain flooding
4. ranking_relevance — top hits plausible vs relevance_notes and category hints (soft judgment; no gold IDs)
5. product_ids — hit ids present and consistent when hits exist

PASS only if the overall retrieval is acceptable for the scenario. FAIL if search was required but missing, wrong domain dominates, or empty results for clear product intent.
